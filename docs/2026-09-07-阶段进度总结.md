# ragbase 阶段进度总结

> 日期：2026-09-07
> 阶段：Phase 1（MVP 最小闭环）完成

## 1. 项目背景

ragbase 是**企业知识库问答产品**：多格式文档入库 → 向量化检索 → AI 问答（带溯源）。

- 定位：服务化部署的 Web 产品（多人使用、管理后台、权限管控）
- 来源：Agent 引擎复用 HippoBuddy，知识底座设计借鉴 ragent，但只保留必需中间件
- 技术栈：Java 21 + Spring Boot 3.5.0，唯一外部中间件 PostgreSQL + pgvector

## 2. 已完成工作

### 2.1 项目骨架
- Spring Boot 3.5.0 + Java 21，Maven 单工程多包
- 模块划分：knowledge（入库）/ search（检索）/ ai（Embedding + LLM）/ chat（问答）/ session / admin / config / common
- 统一响应 `Result`、业务异常、全局异常处理

### 2.2 数据库
- `ragbase` 库 + pgvector 扩展（Docker：pgvector/pg16）
- 6 张表：kb / doc / chunk / ingest_task / conversation / user
- chunk 表含 `vector(1024)` 向量列 + HNSW 索引 + FTS GIN 索引

### 2.3 入库 Pipeline（最小闭环）
- 上传文档（multipart）→ Tika 解析 → 递归字符分块（800 字符 + 100 overlap，句号/换行断句）
- BGE-M3 Embedding（OpenAI 兼容 API，硅基流动）
- 批量写入 pgvector（PGvector JDBC）
- 异步执行（@Async）+ 任务进度追踪
- 已修复：PG 驱动 `RETURN_GENERATED_KEYS` 返回整行问题，DAO 统一改 `RETURNING id`

### 2.4 检索
- 双通道：向量检索（余弦相似度，HNSW）+ 关键词检索（LIKE 子串，中文可命中）
- RRF（Reciprocal Rank Fusion）融合排序

### 2.5 问答（SSE 流式）
- OpenAI 兼容 LLM 客户端（DeepSeek），流式输出
- 检索上下文组装（带来源编号）+ system prompt 约束（不编造、可标注来源）
- SSE 事件：delta（回答增量）/ sources（来源引用）/ error
- **SSE 批量缓冲**：50 字阈值 / 80ms 时间窗聚合，事件数从逐字 ~100+ 降到 ~5

## 4. 关键决策（记录原因）

| 决策 | 原因 |
|:---|:---|
| 语言选 Java/Spring 而非 Python/TS | 企业级服务化能力最强；两个参考项目均为 Java，存量可复用；AI 应用层本质是 HTTP API 调用，语言差异不在 AI 能力 |
| 中间件只有一个 PostgreSQL | pgvector（向量）+ FTS/ILIKE（关键词）+ 业务表三合一，避免 ragent 的 ES+Milvus+RocketMQ 复杂度 |
| 不做记忆模块 | 百万上下文窗口时代，全量历史 + 缓存命中优于摘要压缩型记忆（参考 HippoBuddy JSONL 方案） |
| 不做意图树 | function calling / 简单分类路由即可 |
| 中文关键词用 LIKE（MVP） | PG 内置 simple/english 分词器不支持中文（ragent 用 ES+IK 分词，我们保持单中间件原则，后续可装 pg_jieba/zhparser） |
| 文档解析用 Tika | Java 解析事实标准，不造轮子 |
