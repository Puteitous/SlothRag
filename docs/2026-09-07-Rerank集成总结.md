# Rerank 集成总结

> 日期：2026-09-07
> 内容：检索精排（Rerank）接入 + 证据闸门 + 检索链路修复

## 1. 背景

MVP 阶段边界判据用的是**向量相似度阈值**（maxSimilarity），但"语义相似 ≠ 真正相关"——Rerank 模型专门判断 query-doc 相关性，精度更高。参考 ragent 的 `RerankPostProcessor` + `EvidenceGatePostProcessor` 设计，接入 Rerank 精排。

## 2. 参考 ragent 的设计

| ragent 组件 | 作用 | 本项目的对应 |
|:---|:---|:---|
| `RerankClient` 接口 | 多供应商抽象 | `ai/rerank/RerankClient` |
| `RerankPostProcessor` | 融合后重排 + 出分 | `SearchService.rerank()` |
| `EvidenceGatePostProcessor` | 整批最高精排分 < 阈值 → 整批拒绝 | `ChatService.belowGate()` |

**裁剪**：不搬 ragent 的多供应商路由 + 模型熔断（过度），只做单一供应商 + 失败回退。

## 3. 实现内容

### 3.1 新增
- `ai/rerank/RerankClient` 接口：`rerank(query, documents, topN)`
- `ai/rerank/SiliconflowRerankClient`：硅基流动 `/v1/rerank`（Cohere 风格）
- `config/SearchProperties`：`rerank-enabled` / `rerank-candidates` / `context-top-k` / `min-rerank-score`
- `SearchService`：RRF 融合后调 Rerank 重排 + 出分（`rerankScore`），失败回退 RRF 排序
- `ChatService.belowGate()`：有 Rerank 分时用 `minRerankScore` 判据，否则回退 `minSimilarity`

### 3.2 检索链路
```
问题 → 向量检索(8) ∥ 关键词检索(8, LIKE) → RRF 融合(8) → Rerank(6) → 证据闸门 → LLM
```

## 4. 调试中修复的问题（踩坑记录）

### 4.1 硅基流动 Rerank 模型已下架
`BAAI/bge-reranker-v2-m3` 返回 `code=20015 参数无效`——该模型已不在官方 model 列表。**改用 `Qwen/Qwen3-Reranker-8B`**（文档确认的可选模型）。

### 4.2 硅基流动错误响应是 HTTP 200 + body 业务错误码
`{"code":20015,"message":"..."}` 以 HTTP 200 返回，`response.isSuccessful()` 判定为成功 → 原实现静默返回空结果 → 检索被误判为空 → 连知识内问题也被拒绝。**修复：解析 body 显式识别 `code` 字段**。

### 4.3 关键词通道整句 LIKE 永远命中不了中文
原实现 `LIKE '%整句问题%'`——chunk 里不存在连续整句，`keywordHits` 恒为 0（被向量通道掩盖未暴露）。**修复：启发式中文切词**（[SearchService.extractKeywords](file:///E:/Trae_projects/ragbase/src/main/java/com/ragbase/search/service/SearchService.java#L132-L156)）：
- 去标点/空白
- 按停用词（单字表 + 双字表）切段
- 保留长度 ≥ 2 的片段做 OR-LIKE
- 例："年假有几天" → `["年假"]` → 命中；"加班费怎么算" → `["加班费"]`

### 4.4 增量编译掩盖编译错误
缺 `ArrayList` import 导致 clean 编译失败（之前增量编译用旧 class 通过，运行时 `Unresolved compilation problem`）。教训：**改完代码建议 `mvn clean compile` 而非增量**。

## 5. 阈值校准（实测数据）

| 问题 | Rerank 分数 | 判定 |
|:---|:---|:---|
| "年假有几天"（相关） | 0.122 | 通过（> 0.05） |
| "今天北京的天气怎么样"（无关） | 0.000 | 拒绝（< 0.05） |

`min-rerank-score` 初始设 0.3 导致相关知识被误杀，**实测校准为 0.05**。真实多块文档下分数通常更高，上线前需按实际数据再校准。

## 6. 当前配置

```yaml
ai:
  rerank:
    base-url: https://api.siliconflow.cn
    api-key: ${RERANK_API_KEY:...}
    model: Qwen/Qwen3-Reranker-8B
kb:
  search:
    rerank-enabled: true
    rerank-candidates: 8
    context-top-k: 6
    min-rerank-score: 0.05
  chat:
    min-similarity: 0.35      # Rerank 关闭时的回退判据
    out-of-scope-message: "很抱歉，这个问题超出了当前知识范围，建议联系人工客服（转8001）进行咨询。"
```
